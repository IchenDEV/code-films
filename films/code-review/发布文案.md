## 上一期为什么跑得好（推测，待数据验证）

《Anthropic 把 Git 换掉了》是目前数据最好的一期。从片子本身能看出的差别：

1. **标题是一条“新闻 + 冲突”**：大公司 + 人人都用的工具 + 一个激进的动词（换掉了）。程序员看到会本能地想反驳或求证，非程序员也听说过 Git。
2. **赶上了新鲜度**：博客 10 月 13 日发，片子隔天就出。
3. **第一帧就是结论**，不是铺垫；数字具体（2500 → 3 万）。
4. **评论区有得吵**：“这不就是 Piper / Sapling”“工程师对 Claude 说不”。

这一期照着这四点做：标题是同一个句式（Anthropic + 不再逐行审代码了），博客 10 月 15 日发，第一句就是结论，评论区话题更大（“出了事谁负责”人人有观点）。

## 这一期的打法

| 手段 | 片里怎么做 | 为什么 |
|---|---|---|
| **第一帧就是冲突** | 0 秒：一个人举着放大镜，面前是往上狂涌的代码，PR 还在不停往下砸；第一句“Anthropic 的工程师，已经不逐行看代码了”，念到“不逐行”时放大镜掉下去、盖章 | 一句话就引出“那出事谁负责？”，划到的人想听答案 |
| **反常识的数** | 合并翻了一倍多，回滚比例反而降了四成多：“人看得少了，怎么反而更稳？” | 和直觉相反的结果最能留人，也最好转述 |
| **系列感** | 压力段落出现“上期：Anthropic 把 Git 换掉了”的回顾标签，数字也是同一组（博客自己也引用了） | 看过上期的人会认出来；没看过的人会去翻上一期 |
| **一个好记的画面** | 六层筛子：虫子往下掉，每层拦住一些，极少数掉进回滚的网 | 一张图讲清“不靠一道门，靠很多层”，适合截图转发 |
| **中段二次钩子** | 第 61 秒左右：“最离谱的一次：AI 写、AI 审，一个 PR 一晚上改了 50 多轮” | 短视频在中段掉人最多；荒诞的小故事把人拉回来 |
| **金句** | “AI 的批准，永远不算人的批准”“你合进去的，你负责”（原文是团队默契，不是硬规定）“从‘人看过’变成‘有人负责’” | 评论区和转发时会被引用 |
| **身份投票** | 片尾：你们团队代码谁在审？1 全靠人逐行看 · 2 AI 先审，人再看 · 3 低风险让 AI 直接合 · 4 没人审，线上见 | 每个写代码的人都有答案，打一个数字几乎零成本；第 4 项留了个自嘲的口子 |
| **收藏理由（长版）** | B 站 / YouTube 结尾前有一张“可以照抄的清单” | 收藏是 B 站和小红书的重要信号 |
| **分平台、分语言** | 竖屏短版讲故事（1:49），横屏长版讲全细节（4:56，六层逐层拆开） | 抖音要快，B 站愿意看细节 |

**不做的事**：不编数字、不做兑现不了的标题。“不再逐行看代码”出自原文 “our jobs have moved from reading every diff to the decisions machines are bad at”；片中也明确说了“没有取消审查”，高风险代码、架构这些仍由人看。数字全部出自博客，画面上常驻出处。

**建议的测试**：抖音和视频号同一天发；TikTok、Reels、Shorts 同一条英文短版同时发。三天后和上一期对比 5 秒完播率、完播率、评论率。看中段（60 秒附近）的留存曲线有没有被“一晚 50 轮”拉住；如果投票评论多，下一期继续用身份投票。

**发布时间**：抖音 12:00 或 18:00–21:00；视频号 20:00–22:00；小红书 12:00 / 21:00；B 站周五晚或周末下午；TikTok / Reels 北京时间早上 8–10 点（美国晚间）；YouTube 不挑时间。

**评论区运营**：发布后第一个小时回复前 20 条评论；置顶投票评论。常见质疑与回法：

- “AI 审 AI 不靠谱” → 原文也说了：AI 的批准不算人的批准，中高风险必须有人点头。
- “那出事算谁的” → 原文：谁指挥 AI 写的，谁就算一个审核人；你合进去的，你负责。
- “我们公司做不到” → 原文最后有一张清单，从一个仓库、一个 REVIEW.md 开始。
- “又是 Anthropic 自己吹” → 片子只转述了他们公开的数字；原文也承认还没有“指标变坏就自动收紧审批”的熔断机制。
