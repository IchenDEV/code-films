## 这一版换了什么打法

之前几部的反馈：慢、前三秒抓不住人、看完没有理由互动。这一部从做法上换掉：

| 手段 | 片里怎么做 | 为什么 |
|---|---|---|
| **第一帧就是冲突** | 0 秒：一根标着 git 的管子被改动堵死，告急灯在闪；第 1 秒“换掉”盖章；第一句就是结论“Anthropic 把 Git 换掉了” | 不铺垫、不放片名；划到的人一眼看到“出事了” |
| **具体数字** | 2500 → 3 万次 / 天、100 GB、2500 万次检出、600 PB、1/200、20 倍、4 倍、7 个人 5 个月 | 数字比形容词可信，也是转发时最好复述的东西。全部出自博客原文，画面上常驻出处 |
| **快节奏** | 短版平均 3.4 秒一句，每句都有一个画面动作；每个关键词念到时数字“砸”下来、镜头顶一下、配一个音效 | 画面一直在变，没有可以划走的空当 |
| **竖屏常驻标题 + 进度条** | 顶部从第一帧就写着“每天 3 万次合并，Git 成了瓶颈 / 7 个人、5 个月，换掉了它”，下面一条带章节刻度的进度条 | 中途划进来的人也知道在看什么；进度条让人愿意看完 |
| **悬念** | 开头“7 个人、5 个月，怎么做到的？”，到后面才兑现（“AI 惹的麻烦，AI 收拾”、新模型从头写一遍） | 开着的问题把人留到答案出现 |
| **反常识** | 工程师最常做的事，是对 Claude 说“不” | 和“AI 取代程序员”的常见说法相反，值得评论区争 |
| **站队评论** | 片尾：下一个被 AI 挤爆的是？1 CI / 构建 · 2 代码审查 · 3 合并队列 · 4 我们自己 | 打一个数字几乎零成本；评论数是推荐的第一信号 |
| **社交货币** | 视频号片尾：“转给你们组写代码最快的人” | 转发是视频号的主要分发方式 |
| **分平台、分语言** | 中文 Pangge、英文 Jon 各自一条完整旁白；竖屏短版 1:30，横屏长版讲全细节（六条原则、变更集、三层缓存、合并队列……） | 抖音 / TikTok 要快，B 站 / YouTube 的观众愿意看细节 |

**不做的事**：不编数字、不做兑现不了的标题。“把 Git 换掉了”指的是他们的单体仓库（博客原话：fully migrated our monorepo from git）；片中也明确说了 Scion 不是通用的 Git 替代品。

**建议的测试**：抖音和视频号同一天发；TikTok、Reels、Shorts 同一条英文短版同时发。三天后对比 5 秒完播率、完播率、评论率。B 站和 YouTube 发长版，看平均观看时长落在哪一章，下一部按掉人最多的那一章改节奏。

**发布时间**：抖音 12:00 或 18:00–21:00；视频号 20:00–22:00；小红书 12:00 / 21:00；B 站周五晚或周末下午；TikTok / Reels 北京时间早上 8–10 点（美国晚间）；YouTube 不挑时间。

**评论区运营**：发布后第一个小时回复前 20 条评论；置顶投票评论；有人说“这不就是 Google Piper / Meta Sapling 吗”时，回他“对，博客自己也说借鉴了它们”（博客原文提到这两个先例）。

>
> 他们想明白一件事：Git 是为离线、分布式设计的，可他们的客户端几乎都是永远在线的智能体和自动任务。于是一个 7 人小组用 5 个月造了 Scion：客户端永远在线、服务器包揽一切、所有查询都是 API、横向扩展、提交轻快无锁、工作副本可选。结果：CPU 和内存只要原来 Git 镜像的两百分之一，检出从几分钟变成几秒，CI 省回 25% 的 CPU。

## YouTube（英文长版）

**Title**：Anthropic Replaced Git: 30,000 Merges a Day, 7 Engineers, 5 Months (Scion Explained)

**Description**

> In May 2026, Anthropic merged about 2,500 changes a day. By September, over 30,000. Their monorepo's main-branch history is almost 100 GB, CI checks it out about 25 million times a day, and fetched naively that would be over 600 PB of traffic per day.
>
> Git was designed for offline, distributed work. Nearly all of Anthropic's clients are always-online agents and jobs. So a team of seven built Scion in five months: always-online clients, server-side commits with no push, every query as an API, no full copy of the repo anywhere, cheap lock-free commits, and optional sparse working copies. The result: 200× less CPU and memory than their old git mirrors, checkouts in seconds instead of minutes, and 25% of CI CPU back.
>
> Then the lessons: a new model rewrote a hand-written pipeline with 20× less memory and 4× the speed; engineers' most common job was telling Claude "no"; every component got a Claude "superfan"; and merge queues lost their global lock. And why this is not a general Git replacement, but a class of problem many teams may hit within 6 to 12 months.
