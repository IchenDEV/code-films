# 写程序，越来越像治理一个组织 · Programming as Governance

> 我不再亲手给 AI 派活了，现在是 AI 管 AI。  
> *I no longer dispatch tasks to AI myself. Now AI manages AI.*

根据 IDEVLAB 原创文章《写程序，越来越像治理一个组织》（全文存档见 [brief/article.md](brief/article.md)）制作：从亲手写函数，到像技术负责人一样给 Agent 拆任务、做审查、给 Agent 劝架，再到让 Agent 管 Agent。当管理几千人的人不可能亲自审每个 PR，写程序也开始变成维护一套让工作自主运转的机制——拆不拆任务、拿什么算完成证据、痛觉越级报警，以及在死循环时改机制而不是给提示词打补丁。出处逐条见 [CREDITS.md](CREDITS.md)。

与前两部（《Anthropic 把 Git 换掉了》、《Anthropic 不再逐行审代码了》）不同，本片换成亮色的包豪斯海报风：米色底、红蓝黄黑的大色块和几何形、粗黑描边。胶囊小机器人代表 Agent，戴环的黄色小机器人是协调者，纯 Canvas 2D 程序绘制。

## 结构

- **短版（抖音、视频号 · 1:41）**：按原文核心故事线推进：钩子（我不再亲手给 AI 派活，现在是 AI 管 AI）→ 以前/后来（写函数、像技术负责人）→ 职责往上一层（管几千人的人管机制）→ 机制的三个例子（拆不拆、怎样算做完、什么交给人）→ 中段二次钩子与纠偏（死循环、救火、擦屁股、改机制）→ 注意力的变化（从代码到交付到系统自主做对）→ 结尾愿景与身份投票。短版不念书名，画面角落展示书本封面与出处。
- **长版（B 站 · 6:07）**：完整展开原文，8 本管理学经典全讲到，逐条对应管理学思想。

| 段落 | 讲什么 | 涉及著作 / 核心概念 | 配乐与情绪 |
|---|---|---|---|
| **开场** (0:00) | 从写函数到带 AI，再到让 Agent 管 Agent；写程序越来越像治理组织 | 第一人称叙事转变 | 温暖起步，渐进铺开 |
| **职责再往上一层** (0:34) | 技术负责人能亲自盯代码，但管几千人的管理者不可能亲自审每一个 PR；管的是让工作跑下去的机制 | 组织层级跃迁 | 思考感上升 |
| **管前提，不管决定** (0:55) | 为什么不看代码组织也能正确运转？管理决策前提而非具体微操；管聪明人靠上下文 | 赫伯特·西蒙《管理行为》(1947) · 决策前提 / 有限注意力；《不拘一格》(2020) · 上下文而非控制 | 沉静，理性长音 |
| **拆不拆** (1:26) | 任务交给一个还是多个 Agent？并行不一定快，边做边商量最费协调 | 詹姆斯·汤普森《行动中的组织》(1967) · 互惠依赖与协调成本 | 律动渐强，对比推导 |
| **临时小组** (1:52) | 不预设僵化科层岗位，面对多变研发采用随聚随散的敏捷小组 | 亨利·明茨伯格《卓有成效的组织》(1983) · 特别小组 (adhocracy) | 节奏轻快敏捷 |
| **怎样才算做完** (2:10) | 不微操流程时，靠产出标准化粘合组织；说写完不作数，必须拿真实证据验收 | 明茨伯格 · 产出标准化；严格验收契约 | 沉稳笃定 |
| **什么交给人** (2:34) | 按成熟度放权；组织如神经系统，平时内脏自运转，高风险时痛觉直插底层越级熔断 | 安迪·格鲁夫《格鲁夫给经理人的第一课》(1983) · 任务相关成熟度；斯塔福德·比尔《企业之心》(1979) · 痛觉信号与越级探针 | 张力聚拢，警示感 |
| **纠偏，不是救火** (3:11) | 机制初成难免犯错；两个 Agent 互相否定的死循环；亲自救火下次照样冒烟 | 实际协作踩坑经历 | 荒谬、自嘲（轻笑、叹气） |
| **改机制** (3:29) | 改参数杠杆最低，改信息流的结构、改写规则杠杆高得多；追问为什么反复发生；改机制而不是在提示词加“以后请注意” | 德内拉·梅多斯《系统之美》(2008) · 杠杆点；系统级纠偏 | 坚定，豁然开朗 |
| **让系统自己运作** (4:18) | 不照搬传统官僚形式，不搞层层开会；管理的目的不是制造更多管理，而是降低协调成本 | 传统管理的骨架（目标、责任、授权、反馈） | 舒展开阔 |
| **注意力变了** (4:55) | 从前关心代码写没写对，后来关心任务交没交付，现在关心我不在时系统能否一直做对 | 三次注意力拉远 | 温暖而深沉 |
| **88 年前的一句话** (5:08) | 组织是“两个或更多人有意识地协调起来的活动或力量的系统”；规定组织的目的是经理人的职能之一，作者认为系统跑起来后这是最不能交出去的一项 | 切斯特·巴纳德《经理人员的职能》(1938) | 历史回响，庄重共鸣 |
| **结尾** (5:28) | 过去组织代码，现在组织 Agent；期待有一天不再指挥它们，只需想清楚到底创造什么；片尾投票 | 终极愿景与身份投票 | 宁静悠远，余音绕梁 |

## 视觉

包豪斯海报风的“活的组织”：米色底，背景里有大的几何色块（黄圆、蓝半圆、红长方形），角色和路径都有粗黑描边。
- 胶囊形状的小机器人是 Agent（颜色 = 专长：蓝、青、橙、浅蓝、橄榄绿）；
- 戴环的黄色小机器人是协调者；
- 穿红衣服的人站在边缘定方向；
- 任务沿着路径流动，绿色是授权范围，红色是越级的警报和关键词；
- 被引用的经典是一本本精装书，出现在画面角落。

全部由 Canvas 2D 程序绘制。初版用的是暖黑夜色、发光的画面，作者看过后觉得和前几部（五年、Git、代码审查）一个调子、看着不舒服，于是换成这一套亮色。引擎里保留了三套主题（`web/engine.js` 的 THEMES：night、paper、poster），`?theme=` 可以切换。

## 制作命令

```bash
./run.sh governance tts         # 旁白（短版 / 长版），整条一次合成、转写核对、按段落分开，并排时间轴
./run.sh governance music       # 作曲 + 铺底长音
./run.sh governance sfx         # 音效库
./run.sh governance mix         # 混音 → out/mix/*.wav（-14 LUFS），检查掉空与跳变
./run.sh governance smoke       # 每个转场逐帧画一遍
./run.sh governance render      # → out/deliver/*.mp4
./run.sh governance covers      # → out/deliver/covers/
./run.sh governance extras      # → out/deliver/*.srt、chapters.json
./run.sh governance stills douyin @pain+3 @finale%80 --sheet
./run.sh governance dev pain v 8 1 "alarm:3,skip:5" 2 4 6   # 开发用：不要时间轴，单独画一个镜头
./run.sh governance preview douyin
```

试听工具：`python3 tools/audition.py <稿子.txt> [名字…]`（几组声音 / 模型各念一遍，量音高起伏、语速、停顿）。
